Quick Start

Get up and running in three steps. No internet needed after the initial wheel unpack.

1

Unpack Dependencies

One-time setup — extracts pre-vendored Python wheels.

bash vendor/install.sh
2

Store Your API Key

Saved securely with owner-only permissions.

mkdir -p ~/.daisy
echo 'sk-ant-...' > ~/.daisy/api_key
chmod 600 ~/.daisy/api_key
3

Run Daisy

Single-shot or interactive — your choice.

# Single question
bin/daisy "Show disk usage on /data"

# Interactive session
bin/daisy --interactive

# Named session (auto-saved, resumable)
bin/daisy --interactive --session my-project

System Architecture

How the pieces fit together — from your terminal to Claude and back.

How the Agent Loop Works

Daisy uses a tool-use loop: Claude can request tool calls, Daisy executes them locally, and feeds results back until Claude has a final answer.

What happens at each step

StepWhat happensWhere
1User types a message (single-shot or interactive)cli.py
2Message + conversation history + tool definitions sent to Claude API (with retry on failure)agent_loop.py
3aClaude returns text — printed to user, session savedagent_loop.py
3bClaude requests tool calls — each tool executed locally, results sent back, loop repeatstool_registry.py

Tools Reference

Daisy gives Claude 12 tools it can call during a conversation. Tools are executed locally on your server — results are fed back to Claude automatically.

Memory Tools

save_memoryMemory

Save information for later retrieval across conversations.

key (required) · value (required) · tags (optional array)

search_memoryMemory

Search saved memories by keyword (substring match) or exact tag.

query (optional) · tag (optional)

delete_memoryMemory

Delete a saved memory by its key.

key (required)

list_memoriesMemory

List all memory keys with tags and last-updated timestamps.

No parameters

File & Search Tools

read_fileFile

Read file contents. Returns up to 100K characters with truncation flag.

path (required)

write_fileFile

Write content to a file. Creates parent directories if needed.

path (required) · content (required)

list_directoryFile

List directory contents with file types and sizes.

path (optional, default: cwd)

search_filesFile

Regex content search — returns matching lines with file paths and line numbers. Recursive.

pattern (required) · path · include (glob filter) · context_lines

find_filesFile

Find files by glob pattern (e.g. *.sdc, *.log). Recursive.

pattern (required) · path (optional)

directory_treeFile

Recursive directory tree with configurable depth limit. Good for project overview.

path (optional) · max_depth (1-5, default: 3)

Execution Tools

run_commandExec

Execute a shell command. Returns stdout, stderr, and exit code. Interactive mode asks for confirmation.

command (required) · timeout (default: 30s, max: 300s)

run_pythonExec

Execute a Python script. Ideal for multi-line log parsing, data analysis, and report generation.

code (required) · timeout (default: 60s, max: 300s)

Execution tools are disabled with --no-shell. Output is truncated at 50K characters. API keys are scrubbed from subprocess environment.

API Key Setup

Daisy checks three sources for your API key, in priority order:

Priority 1 — CLI Flag
bin/daisy --api-key 'sk-ant-...' "Hello"

Overrides everything. Good for one-off testing.

Priority 2 — Environment Variable
# bash
export ANTHROPIC_API_KEY='sk-ant-...'

# csh/tcsh
setenv ANTHROPIC_API_KEY 'sk-ant-...'

Good for shell sessions. Disappears on logout.

Priority 3 — Key File (Recommended)
mkdir -p ~/.daisy
echo 'sk-ant-...' > ~/.daisy/api_key
chmod 600 ~/.daisy/api_key

Persistent, secure, works across all shells. Daisy warns if permissions are too open.

Data & Storage

All Daisy data lives under ~/.daisy/ with strict permissions.

~/.daisy/   (all directories mode 0700 — owner only)
  ├ api_key   chmod 600 · your Anthropic API key
  ├ memory/
  │   └ memories.json   persistent key-value store · atomic writes
  ├ sessions/
  │   └ <name>.json   conversation history · auto-saved each turn
  └ logs/
      └ daisy-<id>-<date>.jsonl   audit events · one file per session

Security Features

Designed for enterprise deployment on shared multi-user servers.

  • API key file at ~/.daisy/api_key with chmod 600 — warns if permissions are too open
  • ANTHROPIC_API_KEY is stripped from subprocess environment — run_command and run_python cannot leak your key
  • All ~/.daisy/ directories created with mode 0700 — only owner can read memory, sessions, and logs
  • Audit logging records every API call, tool execution, and shell command (metadata only, no content)
  • Interactive mode shows confirmation prompt before executing shell commands and Python scripts
  • API calls use exponential backoff retry (4 retries: 2s, 4s, 8s, 16s) — auth errors fail immediately
  • Context window warning at 150K input tokens — prevents silent degradation
  • Session names are sanitized to prevent path traversal
  • Memory and session files use atomic writes (tempfile + rename) — no corruption on crash
  • Corrupted JSON files recover gracefully — app never becomes unlaunchable
  • All traffic goes through the corporate HTTP proxy (httpx honors HTTPS_PROXY)
